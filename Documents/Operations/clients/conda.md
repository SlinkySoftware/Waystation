# Conda clients

How to point conda, mamba / micromamba and pixi at a Waystation **conda** repository (a channel). The repository's
**Set me up** tab shows the same snippets with your real URL filled in. Examples below use
`https://waystation.example.com` and repositories called `conda-forge` (a proxy of the conda-forge channel) and
`conda-internal` (hosted).

Status (T-P6-CONDA): proxy and hosted channels. Verified by the real-client harness (`tests/clients/conda/`) with
micromamba 2.3: an environment created through a proxy of conda-forge, `.conda` and `.tar.bz2` packages uploaded to a
hosted channel and installed with an API token, an anonymous install from the hosted channel refused. conda and pixi
use the same protocol (repodata files and package files) but are not yet in the harness.

## Repository types

- **Proxy**: caches one channel (default `https://conda.anaconda.org/conda-forge`; any channel URL works, e.g.
  `https://conda.anaconda.org/bioconda`). Repodata files are streamed to the client while they are cached and
  revalidated after the repository's metadata max age; packages are checked against the sha256 and size the repodata
  lists before they are kept, and kept for good (a package file never changes).
- **Hosted**: your own packages, uploaded with an HTTP `PUT`. The repodata is regenerated by a worker within seconds
  of every upload or delete.
- **Groups are not supported**: list several channels in the client instead (conda merges them by channel priority).

A repository's channel URL is `https://waystation.example.com/repository/<name>` (no trailing slash needed).

## conda, mamba and micromamba

`~/.condarc` (Windows: `%USERPROFILE%\.condarc`; micromamba also reads `~/.mambarc`):

```yaml
channels:
  - https://waystation.example.com/repository/conda-forge
channel_priority: strict
show_channel_urls: true
```

Remove `defaults` (or add `--override-channels`) so nothing bypasses Waystation. To keep environment files that say
`-c conda-forge` working unchanged, name the repository after the channel and map the name:

```yaml
custom_channels:
  conda-forge: https://waystation.example.com/repository
channels:
  - conda-forge
```

One-off: `conda install --override-channels -c https://waystation.example.com/repository/conda-forge numpy`, or
`micromamba create -n demo --override-channels -c https://waystation.example.com/repository/conda-forge numpy`.

## pixi

```toml
[workspace]
channels = ["https://waystation.example.com/repository/conda-forge"]
platforms = ["linux-64", "osx-arm64", "win-64"]
```

## Credentials

Hosted channels (and proxies you made private) need an API token (Profile → API tokens; `read` to install, `write`
to upload, `delete` to delete):

- **conda**: `~/.netrc` (chmod 600; Windows `%USERPROFILE%\_netrc`):
  ```
  machine waystation.example.com
    login <your username>
    password <API token>
  ```
  or the credentials in the channel URL: `https://<username>:<API token>@waystation.example.com/repository/conda-internal`.
- **micromamba / mamba**: the credentials in the channel URL, as above.
- **pixi**: `pixi auth login waystation.example.com --token <API token>` (sent as a bearer token).

Waystation answers `401` with a challenge when a channel needs credentials and none were sent; a hidden or missing
channel answers the same way.

## Uploading to a hosted channel

`PUT /repository/<repo>/<subdir>/<file>` with the package file as the body. The subdir must be the one in the
package's `info/index.json` (`noarch` for noarch packages):

```shell
curl -fu <username>:<API token> --upload-file dist/noarch/my-pkg-1.0-py_0.conda \
  https://waystation.example.com/repository/conda-internal/noarch/
```

Both `.conda` and `.tar.bz2` packages are accepted. The file name must be `<name>-<version>-<build>` as in
`info/index.json`. With the default write policy an existing file cannot be replaced with other bytes (409; the same
bytes again answer 200). Delete with `curl -fu ... -X DELETE https://.../conda-internal/noarch/my-pkg-1.0-py_0.conda`.

## Troubleshooting

- **A new upload does not resolve yet**: the repodata is regenerated by the worker (`index.conda` task on the Tasks
  page); it normally takes a few seconds. Clients cache repodata too: `conda clean --index-cache` or
  `micromamba clean --index-cache`.
- **`400` on upload**: the file name or subdir does not match `info/index.json`, or the archive is not a valid conda
  package (the message says which).
- **Slow first install from a big channel**: the first request for conda-forge's `linux-64` repodata downloads it
  (tens of MB compressed) and indexes it in the background; later requests are served from the cache.
- **`repodata.jlap` 404s in the log**: expected; Waystation does not serve incremental repodata and clients fall back
  to the full file.
- **A package shows "unverified" in the browser**: it was fetched before the repodata listing it was cached; it is
  checked as soon as the subdir's repodata is cached and dropped from the cache if it differs.
