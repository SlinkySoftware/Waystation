# Waystation data model

MongoDB is the system of record; Valkey holds only ephemeral state; the blob store holds file content.
Collection access goes through the `*.db` modules only (ARCHITECTURE §3). IDs are ULIDs (string) unless noted.
All timestamps are UTC `datetime`. Collections and indexes are declared in `waystation_common.db.collections` and
created by `init` (`db.schema.ensure_schema`, idempotent; index names are part of the schema); data changes are
forward-only migrations (`db.migrations`, recorded in `migrations`).

**Search keys** (T-U06, `waystation_common.searchkeys`): every searchable document (`npm_packages`, `pypi_packages`, `go_modules`, `docker_tags`,
`apt_packages`, `yum_packages` listing entries, `assets` of kind `content`) carries `name_lc` (its name lower-cased,
at most 200 characters; files: the last path segment) and, for names with a `/`, `base_lc` (the last segment
lower-cased, so `nginx` finds `library/nginx`). The format index writers set them; migration `0002_search_keys`
backfills older documents (idempotent, batched). Indexes, partial on the key existing: `search_name`
`name_lc,repo_id,_id` on all six collections, and `search_base` `base_lc,repo_id,_id,name_lc` on `docker_tags` and
`npm_packages`. Global search reads prefix ranges of these in index order (no in-memory sort).

- `components.version_sort` is computed by each format (semver, PEP 440, Maven ComparableVersion, Debian
  dpkg order, RPM EVR, Go semver) so "latest N" and sorting are index-backed.
- Large lists (docker layers, file lists) stay in their own documents; no unbounded arrays in hot documents.
- Change streams on `repositories`, `settings`, `rbac_state`, `auth_providers` invalidate replica caches.
  `repositories` (the repository catalog, header-only stream) and `rbac_state` do today; the catalog also reloads
  once when a lookup by name misses (at most once a second and once per name and snapshot) and every 5 s at the
  latest. The provider catalog and the group directory are refreshed every 5 s (and at once on the replica that made
  the change).

## 3. Blob store (`WAYSTATION_DATA_DIR`)
See ARCHITECTURE §5. `blobs/sha256/aa/bb/<hex>`, `uploads/<uuid>`, `keys/<key-id>.enc`. Nothing else is written there. A Helm group's merged `index.yaml` is a blob no asset references (served by X-Accel through an in-process pointer, re-committed when its members change and claimed against GC again every hour while served); blob GC removes old merges after the grace period.
