# ADR 0007: In-house OpenPGP signing and verification on `cryptography`

Status: **Proposed — needs the owner's approval** (drafted 2026-11-10 in T-P5-YUMH). The code below ships behind
`waystation_common.signing` so it can be swapped if this is declined.

## Context
ARCHITECTURE §2 reserves the OpenPGP implementation for hosted apt/yum signing for an ADR ("a Python OpenPGP
library or `gpg` inside the worker image only"; originally planned in T-P5-APTH). Hosted yum (T-P5-YUMH) is the
first task that needs it: `repomd.xml` must be signed (`repomd.xml.asc`) with a per-repository key, generated by
Waystation, stored encrypted with `WAYSTATION_SECRET_KEYS` under `keys/` (ARCH §5), and the public key served by the
repository. The yum proxy (T-P2-YUM) also gained optional verification of an upstream's `repomd.xml.asc` against
operator-configured keys, which needs the same packet format.

What is needed is small: version 4 keys and **detached binary-document signatures** (plus, for apt later, a
clearsigned `InRelease`), RSA or Ed25519, SHA-2. No encryption, no keyring trust model, no key servers.

Options:

1. **`gpg` in the worker image.** The reference implementation, and it would also produce `InRelease` clearsigning.
   Costs: a ~10 MB binary and its agent in the worker image, a per-repository `GNUPGHOME` materialised on disk from
   the encrypted key for every signing (or a long-lived agent holding plaintext keys), subprocess handling and
   output parsing in an async worker, version-dependent behaviour across base images, and nothing for the server
   (the proxy's verification runs in the server, which must stay free of it).
2. **A Python OpenPGP library** (PGPy, pysequoia, ...). PGPy is unmaintained and has known gaps with current
   `cryptography`; pysequoia is a Rust extension with a young Python API. Either adds a dependency mostly for packet
   framing.
3. **In-house on `cryptography`** (already a dependency, ARCH §2). Packet framing, armor, v4 fingerprints and
   signature hashing are a few hundred lines of well-specified code (RFC 9580 / RFC 4880); the cryptography is
   `cryptography`'s RSA PKCS#1 v1.5 and Ed25519.

## Decision (proposed)
Option 3:

- `waystation_common.openpgp` (pure, no I/O): armor (CRC-24), packet framing (definite lengths only), v4 public
  keys and subkeys (RSA, EdDSA legacy and Ed25519), v4 signatures of binary/text documents with SHA-224/256/384/512
  (SHA-1 and MD5 refused; unknown critical hashed subpackets and expired signatures refused), detached verification
  against a set of keys, and the encoders: public key packets, user ID self-certification (positive, key flags
  certify+sign, preferred hashes SHA-512/SHA-256) and detached signatures. Tested against real Rocky Linux and
  AlmaLinux `repomd.xml.asc` signatures and keys, and by real clients: dnf 4 (librepo), dnf 5 and zypper import the
  generated keys and verify the generated signatures in `tests/clients/yum/`.
- `waystation_common.signing` is the only signing entry point (ARCH §2): `KeyStore` keeps one key per repository in
  `keys/<repo id>.json` (0600; the private key as PKCS#8 DER encrypted with AES-256-GCM under `SECRET_KEYS`, bound
  to the repository id as associated data; created atomically by the worker on first use, never rewritten);
  `RepoKey.sign(data)` returns an armored detached signature. Keys are **RSA 3072** (readable by GnuPG 2.0 on EL7
  and every later rpm/apt/gpg; Ed25519 signing can be added later per repository), signatures SHA-512.
- Verification of upstream signatures (yum proxy option `repomd_keys`) uses `openpgp.verify_detached` in the
  server, in the engine's validation thread. Configured keys are trusted as given (binding signatures, expiry and
  revocation of those keys are not evaluated: the operator chose them).
- ARCHITECTURE §2 would read: "OpenPGP signing for apt/yum hosted repos sits behind `waystation_common.signing`,
  in-house on `cryptography` (`waystation_common.openpgp`, adr/0007)", replacing the sentence that defers the choice.

## Consequences
- No new dependency, no subprocesses, no plaintext key material on disk, the same code in server and worker, and
  signing is a fast in-process call (in a thread).
- Waystation owns about 600 lines of OpenPGP code. Kept deliberately narrow (no encryption, no v5/v6 keys, no
  partial-length packets) and covered by unit tests plus real-client interop tests; RFC 9580 v6 keys and
  signatures can be added if a distribution moves to them.
- apt hosted (T-P5-APTH) needs clearsigned `InRelease`: a cleartext-framework encoder (dash-escaping, `Hash:` header)
  on top of `openpgp.make_signature` with a text signature; `Release.gpg` is a detached signature as today.
- Not yet: key rotation (a new key, published alongside the old one for a transition period), exporting or
  importing a repository key through the API, removing a deleted repository's key file, re-encrypting key files
  when `SECRET_KEYS` rotates (old keys stay decryptable while listed).
- **If declined** (option 1): `waystation_common.signing` is reimplemented with `gpg --batch --detach-sign --armor`
  in the worker image (key imported into a temporary `GNUPGHOME` per job from the same encrypted key file format,
  or stored as gpg's export); the worker job, the published files and the tests stay the same. Verification in the
  proxy would then need either this module's verifier kept, or the `repomd_keys` option dropped.
