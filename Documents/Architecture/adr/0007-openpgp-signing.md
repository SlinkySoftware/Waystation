# ADR 0007: In-house OpenPGP signing on `cryptography`

Status: **Proposed — needs the owner's approval** (drafted 2026-11-10 in T-P5-YUMH). The code below ships behind
`waystation_common.signing` so it can be swapped if this is declined.

## Context
ARCHITECTURE §2 reserves the OpenPGP *signing* implementation for hosted apt/yum repositories for an ADR ("a Python
OpenPGP library or `gpg` inside the worker image only"; originally planned in T-P5-APTH). Hosted yum (T-P5-YUMH) is
the first task that needs it: `repomd.xml` must be signed (`repomd.xml.asc`) with a per-repository key generated by
Waystation, stored encrypted with `WAYSTATION_SECRET_KEYS` under `keys/` (ARCH §5), and the public key served by the
repository. Verification is already decided: adr/0006 (accepted) put an in-house verifier on `cryptography` in
`waystation_common.openpgp` (used by the Terraform mirror and, since T-P2-YUM, the yum proxy's `repomd_keys`).

What signing needs is small: generate a key, write a v4 public key packet, one user ID and its self-certification,
and **detached binary-document signatures** (for apt later also a clearsigned `InRelease`). No encryption, no
keyring, no key servers.

Options:

1. **`gpg` in the worker image.** The reference implementation, and it would also produce `InRelease`
   clearsigning. Costs: a ~10 MB binary and its agent in the worker image, a per-repository `GNUPGHOME` materialised
   on disk from the encrypted key for every signing (or a long-lived agent holding plaintext keys), subprocess
   handling and output parsing in an async worker, version-dependent behaviour across base images.
2. **A Python OpenPGP library.** adr/0006 found none usable on Python 3.14 (PGPy does not import; pysequoia's
   policy differs from GnuPG's), and a dependency would only buy packet framing.
3. **In-house on `cryptography`** (already a dependency, ARCH §2): packet framing, armor and v4 signature hashing
   are about 150 lines on top of `cryptography`'s RSA; every packet written is read back by adr/0006's verifier.

## Decision (proposed)
Option 3, in `waystation_common.signing` (the only signing entry point, ARCH §2):

- Packet writers: v4 RSA public key, user ID, positive self-certification (key flags certify + sign, preferred
  hashes SHA-512/SHA-256, primary user ID), detached binary signatures (SHA-512, issuer fingerprint hashed, issuer
  key id unhashed), ASCII armor with CRC-24.
- `KeyStore`: one key per repository in `keys/<repo id>.json` (0600; the private key as PKCS#8 DER encrypted with
  AES-256-GCM under `SECRET_KEYS`, bound to the repository id as associated data; created atomically by the worker
  on first use, never rewritten; a new certificate must read back through `openpgp.read_certs` as a valid signing
  key before it is stored). `RepoKey.sign(data)` returns an armored detached signature. Keys are **RSA 3072**
  (readable by GnuPG 2.0 on EL7 and every later rpm/apt/gpg).
- Interop is tested by real clients: dnf 4 (librepo) imports the generated key from the repository's `gpgkey` URL
  and verifies `repomd.xml.asc` with `repo_gpgcheck=1` (`tests/clients/yum/hosted.sh`); unit tests read every
  written packet back with `waystation_common.openpgp`.
- ARCHITECTURE §2 would read: "OpenPGP signing for apt/yum hosted repos sits behind `waystation_common.signing`,
  in-house on `cryptography` (adr/0007); verification in `waystation_common.openpgp` (adr/0006)", replacing the
  sentence that defers the choice to T-P5-APTH.

## Consequences
- No new dependency, no subprocess, no plaintext key material on disk, signing is a fast in-process call (in a
  thread).
- Waystation owns about 150 lines of packet writing (no parsing of untrusted input: the inputs are its own keys and
  files).
- apt hosted (T-P5-APTH) needs clearsigned `InRelease`: a cleartext-framework writer (dash-escaping, `Hash:` header,
  a text-mode signature) on top of `make_signature`; `Release.gpg` is a detached signature as today.
- Not yet: key rotation (a new key published alongside the old one for a transition), exporting or importing a
  repository key through the API, removing a deleted repository's key file, re-encrypting key files when
  `SECRET_KEYS` rotates (old keys stay decryptable while listed), Ed25519 keys.
- **If declined** (option 1): `waystation_common.signing` is reimplemented with `gpg --batch --detach-sign --armor`
  in the worker image (the key imported into a temporary `GNUPGHOME` per job from the same encrypted key file); the
  worker job, the published files and the tests stay the same.
